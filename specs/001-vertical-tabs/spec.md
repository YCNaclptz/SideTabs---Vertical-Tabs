# Feature Specification: Vertical Tabs Sidebar

**Feature Branch**: `001-vertical-tabs`
**Created**: 2026-01-13
**Status**: Draft
**Input**: User description: "開發一個 VS Code extension，將目前開啟的檔案頁籤改成垂直排列顯示在側邊欄，需要拖曳排序、字體大小/顏色自訂、錯誤/警告顏色提示、未儲存斜體、查看文件路徑、開啟檔案所在位置、自訂 tab 群組（類似 Microsoft Edge 垂直索引標籤）"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - View Tabs Vertically (Priority: P1)

作為一位開發者，我想要在側邊欄以垂直方式查看所有開啟的檔案頁籤，這樣我可以一次看到更多檔案名稱，特別是當檔案名稱較長時。

**Why this priority**: 這是核心功能，沒有垂直頁籤顯示，其他所有功能都無法運作。這是 MVP 的基礎。

**Independent Test**: 安裝擴充功能後，側邊欄出現新的 panel，顯示所有目前開啟的檔案頁籤，點擊任一頁籤可切換到該檔案。

**Acceptance Scenarios**:

1. **Given** VS Code 已安裝此擴充功能且有開啟的檔案, **When** 使用者開啟側邊欄的 Vertical Tabs panel, **Then** 看到所有開啟檔案以垂直清單方式顯示
2. **Given** 側邊欄顯示垂直頁籤清單, **When** 使用者點擊某個頁籤, **Then** 編輯器切換到該檔案
3. **Given** 使用者開啟新檔案, **When** 檔案載入完成, **Then** 新頁籤自動出現在垂直清單中
4. **Given** 使用者關閉某個檔案, **When** 檔案關閉完成, **Then** 對應頁籤從垂直清單中移除

---

### User Story 2 - File Status Indicators (Priority: P2)

作為一位開發者，我想要在頁籤上看到檔案狀態（錯誤、警告、未儲存），這樣我可以快速識別需要注意的檔案。

**Why this priority**: 狀態提示是提升效率的關鍵功能，讓使用者不需要逐一開啟檔案就能知道哪些檔案有問題。

**Independent Test**: 開啟一個有語法錯誤的檔案，其頁籤文字變為紅色；修改檔案但不儲存，頁籤文字變為斜體。

**Acceptance Scenarios**:

1. **Given** 某檔案有錯誤診斷訊息, **When** 側邊欄顯示該檔案頁籤, **Then** 頁籤文字顯示為錯誤顏色（預設紅色）
2. **Given** 某檔案有警告診斷訊息但無錯誤, **When** 側邊欄顯示該檔案頁籤, **Then** 頁籤文字顯示為警告顏色（預設黃色）
3. **Given** 某檔案有未儲存的變更, **When** 側邊欄顯示該檔案頁籤, **Then** 頁籤文字以斜體顯示
4. **Given** 某檔案同時有未儲存變更和錯誤, **When** 側邊欄顯示該檔案頁籤, **Then** 頁籤文字同時顯示斜體和錯誤顏色

---

### User Story 3 - Drag and Drop Sorting (Priority: P3)

作為一位開發者，我想要透過拖曳來重新排序頁籤，這樣我可以將相關檔案放在一起方便切換。

**Why this priority**: 手動排序是組織工作流程的重要功能，但不影響基本的頁籤查看和狀態顯示。

**Independent Test**: 拖曳某個頁籤到另一個位置，放開後頁籤順序更新，重新開啟 VS Code 後順序保持不變。

**Acceptance Scenarios**:

1. **Given** 側邊欄有多個垂直頁籤, **When** 使用者拖曳某頁籤到新位置, **Then** 頁籤順序即時更新
2. **Given** 使用者已重新排序頁籤, **When** 重新開啟 VS Code, **Then** 頁籤順序維持使用者設定的順序
3. **Given** 使用者正在拖曳頁籤, **When** 拖曳到目標位置上方, **Then** 顯示視覺提示表示放置位置

---

### User Story 4 - Tab Groups (Priority: P4)

作為一位開發者，我想要將頁籤分組並可摺疊，這樣我可以更好地組織大量開啟的檔案。

**Why this priority**: 群組功能提供進階組織能力，適合同時開啟大量檔案的使用者，但基本使用者可能不需要。

**Independent Test**: 建立新群組、將頁籤拖曳至群組、摺疊/展開群組、重新命名群組。

**Acceptance Scenarios**:

1. **Given** 側邊欄顯示垂直頁籤, **When** 使用者建立新群組, **Then** 出現可命名的空群組
2. **Given** 已建立群組, **When** 使用者將頁籤拖曳至群組, **Then** 頁籤移入該群組中顯示
3. **Given** 群組內有頁籤, **When** 使用者點擊群組摺疊按鈕, **Then** 群組內容收合，只顯示群組名稱
4. **Given** 群組已摺疊, **When** 使用者點擊群組展開按鈕, **Then** 群組內容展開顯示所有頁籤
5. **Given** 已建立群組, **When** 使用者右鍵點擊群組名稱選擇重新命名, **Then** 可編輯群組名稱

---

### User Story 5 - Appearance Customization (Priority: P5)

作為一位開發者，我想要自訂頁籤的字體大小和顏色，這樣我可以讓它符合我的視覺偏好和工作環境。

**Why this priority**: 外觀自訂是錦上添花的功能，提升使用體驗但不影響核心功能。

**Independent Test**: 在設定中修改字體大小，頁籤清單即時反映新的字體大小。

**Acceptance Scenarios**:

1. **Given** 擴充功能已安裝, **When** 使用者在設定中修改頁籤字體大小, **Then** 側邊欄頁籤文字大小即時更新
2. **Given** 擴充功能已安裝, **When** 使用者在設定中修改錯誤/警告顏色, **Then** 對應狀態的頁籤顏色即時更新
3. **Given** 使用者已自訂外觀設定, **When** 重新開啟 VS Code, **Then** 自訂設定保持生效

---

### User Story 6 - File Path and Location (Priority: P6)

作為一位開發者，我想要查看檔案完整路徑並快速開啟檔案所在資料夾，這樣我可以更容易地在檔案系統中定位檔案。

**Why this priority**: 輔助功能，提供便利但非核心需求。

**Independent Test**: 將滑鼠懸停在頁籤上顯示完整路徑 tooltip，右鍵選單可開啟檔案所在資料夾。

**Acceptance Scenarios**:

1. **Given** 側邊欄顯示某檔案頁籤, **When** 使用者將滑鼠懸停在頁籤上, **Then** 顯示 tooltip 包含檔案完整路徑
2. **Given** 側邊欄顯示某檔案頁籤, **When** 使用者右鍵點擊頁籤並選擇「在檔案總管中顯示」, **Then** 開啟系統檔案管理器並定位到該檔案
3. **Given** 側邊欄顯示某檔案頁籤, **When** 使用者右鍵點擊頁籤並選擇「複製路徑」, **Then** 檔案完整路徑複製到剪貼簿

---

### Edge Cases

- 當開啟超過 100 個檔案時，頁籤清單是否保持流暢滾動？
- 當檔案名稱過長時，結尾省略並顯示開頭（例：UserAuthenti...）
- 當多個檔案同名但在不同目錄時，顯示最少區分路徑（例：index.ts (components)）
- 當群組內的所有檔案都關閉時，群組自動移除
- 拖曳頁籤時：拖曳到群組區塊內（標題或任意成員頁籤上）即放入群組，並以邊界顏色提示目前所在區塊
- 當 VS Code 有多個編輯器群組（分割視窗）時，合併顯示所有頁籤（不區分來源編輯器群組）

## Clarifications

### Session 2026-01-13

- Q: 當群組內所有檔案都關閉時，群組如何處理？ → A: 自動移除空群組
- Q: 多個編輯器群組（分割視窗）時，頁籤如何顯示？ → A: 合併顯示所有頁籤，不區分來源
- Q: 長檔名如何截斷顯示？ → A: 結尾省略，顯示開頭
- Q: 拖曳頁籤到群組邊界如何判定？ → A: 拖曳到群組區塊內（標題或成員）即放入群組，顯示邊界顏色提示目前區塊
- Q: 同名檔案如何區分顯示？ → A: 顯示最少區分路徑（例：index.ts (components)）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 擴充功能 MUST 在側邊欄提供一個專用的 TreeView panel 顯示垂直頁籤
- **FR-002**: 系統 MUST 即時同步 VS Code 編輯器的頁籤狀態（開啟、關閉、切換）
- **FR-003**: 點擊側邊欄頁籤 MUST 切換到對應的編輯器檔案
- **FR-004**: 系統 MUST 監聽 VS Code 診斷訊息並更新頁籤顯示顏色
- **FR-005**: 系統 MUST 監聽檔案變更狀態並以斜體顯示未儲存檔案
- **FR-006**: 使用者 MUST 能透過拖曳重新排序頁籤
- **FR-007**: 系統 MUST 持久化使用者的頁籤排序設定
- **FR-008**: 使用者 MUST 能建立、重新命名和刪除頁籤群組
- **FR-009**: 使用者 MUST 能將頁籤拖曳至群組中或群組外
- **FR-010**: 群組 MUST 支援摺疊和展開操作
- **FR-011**: 系統 MUST 持久化群組設定和狀態
- **FR-012**: 使用者 MUST 能透過 VS Code 設定調整字體大小
- **FR-013**: 使用者 MUST 能透過 VS Code 設定自訂錯誤/警告顏色
- **FR-014**: 滑鼠懸停 MUST 顯示檔案完整路徑 tooltip
- **FR-015**: 右鍵選單 MUST 提供「在檔案總管中顯示」功能
- **FR-016**: 右鍵選單 MUST 提供「複製路徑」功能
- **FR-017**: 當同名檔案存在時，系統 MUST 顯示足夠的路徑資訊以區分

### Key Entities

- **Tab**: 代表一個開啟的檔案頁籤，包含檔案路徑、顯示名稱、修改狀態、診斷狀態、排序位置
- **TabGroup**: 代表一個頁籤群組，包含群組名稱、所屬頁籤列表、摺疊狀態、排序位置
- **UserSettings**: 代表使用者設定，包含字體大小、錯誤顏色、警告顏色等外觀設定
- **TabState**: 代表整體狀態，包含所有頁籤、群組、排序的持久化資料

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 使用者開啟/關閉檔案後，側邊欄頁籤清單在 200ms 內更新
- **SC-002**: 診斷訊息變更後，頁籤顏色在 500ms 內反映變更
- **SC-003**: 頁籤拖曳排序操作回饋延遲小於 100ms
- **SC-004**: 擴充功能在開啟 100 個檔案時，記憶體增加不超過 20MB
- **SC-005**: 頁籤清單滾動在開啟 200 個檔案時維持 60fps 流暢度
- **SC-006**: 90% 的使用者能在 30 秒內找到並使用垂直頁籤功能
- **SC-007**: 群組建立和管理操作能在 3 次點擊內完成
- **SC-008**: 設定變更後，外觀即時反映（小於 100ms）
